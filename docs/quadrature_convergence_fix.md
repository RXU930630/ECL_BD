# rc4：40N混合润滑输运表的积分收敛修正

用户用rc3本地运行后，在首档40N的输运表建立阶段遇到`Pressure-flow quadrature not converged`。Excel输入与载荷转换均已成功。

## 原因与复现

按40N独立建立接触插值表后，第25/163个输运节点位于指定渗流临界间隙：

- 平均间隙：9.177350841473203e-8 m。
- 该插值表给出的接触压力：118403.39947073194 Pa。
- 原模型对应A/A0=0.42的压力：118403.40146348509 Pa。
- 插值压力对应A/A0=0.4199999936238497，略低于0.42。

默认有效导流仍为0，但未解析PDF概率的导流上界为一个极小正值，必须同样通过积分加密检查。旧参数2049初始节点、最多2次加密，只能检查到8193节点；此点尚不满足0.002相对容差，程序因此停止。

改为最多4次加密后，在32769节点满足同一容差：最终相对差约0.00137114，默认K3仍为0，上界约7.38878e-47 m³。没有将失败结果强行接受，也未添加正导流下限或调整接触/流体物理模型。

此前的27工况验证在载荷间共用了由160N设置生成的本构插值表。该表在同一临界间隙处的插值压力略高于临界值，上下界都为0，未触发此相对误差检查。那次验证不能代替按每个载荷分别建立插值表的实际运行路径。

## 修改

- `FlowOptions`和默认parameters中的`max_gap_refinements`由2改为4；仍保留2049初始节点和0.002相对容差。
- 积分失败时提示接触压力、实际使用的节点数、相对误差、容差和可调整参数；混合输运表还会给出节点编号及间隙。
- 新试运行包使用新输出目录`results/silicone_fit_excel_02`，避免覆盖之前失败时留下的诊断文件。
- 增加针对该实际压力节点的回归检查，验证旧上限下确实失败、新上限下收敛，并保持默认物理零导流。

## 旧包的手动修正

```python
'max_gap_refinements': 4,
```

同时将输出目录换成未使用过的名称，再运行`python main.py`。无需重填Excel或更改拟合数据。

## 回归检查

运行`python -m unittest discover -s tests -v`，183项检查全部通过，包含新增的实际临界节点复现、原Fortran流动参考值、零导流、Excel输入/输出和拟合流程检查。

随后按用户完整工况分别为40、100、160N建立各自的接触插值表及163点输运表，每档从头求解9个实验速度，共27个状态。本次未使用共享表或替代求解器。全部状态成功；最大总载荷相对误差1.20e-9，最大几何归一化残差3.41e-9，最大单元面通量极差/最大通量7.23e-7，空化互补积最大值0。

再通过原生saved_forward拟合入口读取这三套新结果与用户Excel实验表，联合拟合正常完成，fit_results.xlsx包含全部27个实验点，21点通过固体接触敏感性阈值参与拟合。计算输出仅保留在验证工作区，不放入纯净包或实验输入下载包。该检查证明此路径的数值收敛与程序衔接，不构成实验准确性或剪切强度可迁移性验证。
